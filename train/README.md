# Training configs (LlamaFactory yamls)

LlamaFactory LoRA training yamls for the three benches, synced from our training
repo (`LlamaFactory-new/`). They let readers reproduce the training matrix in the
paper: model sizes {2B, 4B, 9B}, seeds {7, 13, 17, 23}, and the full ablation
grid (vanilla / rottuning / hammer_fm / HMA-abl4, IDR variants).

| Bench | Dir | # yamls |
|---|---|---|
| τ² telecom | `tau2/` | 48 |
| BFCL live six-scene holdout | `bfcl/` | 45 |
| MetaTool (4 personas) | `metatool/` | 232 |

## What you need

1. **Patched LlamaFactory.** The IDR loss
   (`L = L_CE(anchor) + L_CE(positive) + α · InfoNCE`, the paper's Eq. form:
   each view — clean anchor and mutated positive — receives exactly one
   next-token CE supervision, plus the α-weighted InfoNCE term) is **not**
   in upstream LlamaFactory. It lives in our fork:
   - `src/llamafactory/hparams/finetuning_args.py` — `use_idr_loss`,
     `idr_alpha`, `idr_layer_idx`, `idr_use_contrastive`, `idr_temperature`,
     `idr_use_distributed_negatives`
   - `src/llamafactory/train/sft/trainer.py` — contrastive pair construction and
     the InfoNCE term

2. **Training datasets.** Each yaml's `dataset:` name must be registered in
   LlamaFactory's `data/dataset_info.json`. The pair-jsonl files are produced by
   the build scripts in the training repo (e.g. `toolmind_bfcl/scripts/09_build_hma_abl4.sh`
   builds the BFCL clean↔H_mix_abl4 IDR pairs; analogous scripts build the
   τ² / MetaTool pairs). Typical dataset names:

   | Bench | dataset | Pairs |
   |---|---|---|
   | τ² | `tau2_telecom_hma_abl4` / `..._hma_abl4_idr` | clean ↔ H_mix_impl_abl4 |
   | BFCL | `bfcl_live_scene_holdout_hma_abl4_idr` | clean ↔ H_mix_abl4 |
   | MetaTool | `metatool_occ_{persona}_hma_s9_abl4_idr_Lall` | clean ↔ H_mix |

3. **Model checkpoints.** `model_name_or_path` points to our cluster paths
   (`/media/cfs/.../Qwen3.5-{2B,4B,9B}`). Replace with your local paths
   (or HF ids) — likewise for `output_dir`.

## Run

```bash
FORCE_TORCHRUN=1 NNODES=1 NPROC_PER_NODE=16 \
  llamafactory-cli train tau2/train_tau2_telecom_hma_abl4_idr_Lall_qwen35_4b_lora.yaml
```

## Naming convention

`train_<bench>_<variant>[_<idr-variant>]_qwen35_<size>_lora[_seed<N>].yaml`

- **variant**: `vanilla` (plain SFT) · `rottuning` (rotation baseline) ·
  `hammer_fm` (strongest single-perturb baseline) · `hma_abl4` (HMA, abl4 set)
- **idr-variant** (only on HMA rows): `idr_Lall` (InfoNCE over all layers,
  α=0.1) · `idr_cos` (cosine similarity) · `a0p01/a0p05/a0p2/a0p5`
  (α sweep) · `c0/c25` (contrastive-layer ablation) · `abl2` (+ `abl2_leak`
  leakage control) · on MetaTool additionally `p01/p25`, `L1/Llast/Lp50`
- **size**: `2b` / `4b` / `9b`; default seed is in the seedless file, the
  multi-seed runs are `seed7/13/17/23`

## Notes

- Chat template: `qwen3_6` with `enable_thinking: false` (matches the official
  bench harnesses). This is a LlamaFactory chat-template setting, not a
  perturbation template.
- No perturbation templates exist anywhere in the pipeline: every perturbed
  surface (renames, arg maps, widen descriptions, cover/suite parameters,
  optional schemas) is LLM-generated by `hma_sft/scripts/generate_mix.py`,
  and the apply layer raises instead of falling back to any canned content.
- IDR forward doubles the batch (clean + perturbed); `cutoff_len` is lowered
  to 8192 on BFCL to avoid OOM.
- Operator naming vs paper Table 1 (`tab:protocol-map`): yaml comments that say
  `expand` refer to the paper's **schema reshape** operator (`SchemaReshape`
  in `core/operators.py`); the two names are the same operator. The abl4
  training operator sets correspond to paper Table 1 as follows —
  τ²: {rename, arg_rename, reshape, cover, fold};
  BFCL: {rename, arg_rename, reshape} (the `abl4_c0` yaml, i.e. abl4 without
  cover; plain `abl4` additionally mixes cover, matching the BFCL cover
  ablation row);
  MetaTool: {arg_rename, reshape, cover, fold} by protocol — note MetaTool
  catalogs carry no parameter schemas, so `arg_rename` / `reshape` are
  typically empty on this bench and the effective training surface is
  {cover, fold}: all 8 official tools stay in the cover family (new name +
  expanded description) with two products folded into one suite; tool
  rename is not used on this bench at training time. The cover/rename
  split of the last 4 tools in `adapters/metatool.py` is an eval-only
  attribution for the full evaluation operator set.
